# 日常财务管理系统 — 后台管理系统 PRD V1.0

> **版本**：V1.0  
> **日期**：2026-09-29  
> **状态**：需求梳理（功能点规划）  
> **范围**：运维后台管理功能（独立于用户端前端应用）

---

## 一、产品概述

### 1.1 产品定位

面向系统运维/管理人员的后台管理系统，用于查看和管理「日常财务管理系统」中所有用户数据、储备金、账单记录及支出分类，保障系统数据可控、可查、可管理。

### 1.2 目标用户

- 系统运维人员
- 后台管理人员
- 不涉及普通 C 端用户

### 1.3 核心价值

| 价值点 | 说明 |
|--------|------|
| **用户管理** | 查看所有注册用户信息，掌握用户规模与活跃度 |
| **数据总览** | 汇总查看用户储备金、支出等核心财务数据 |
| **分类管理** | 管理系统预设的支出/储备金分类，支持新增和删除 |
| **只读优先** | V1.0 以数据查看为主，避免误操作影响用户数据 |

## 二、系统架构概述

### 2.1 与现有系统的关系

```
┌─────────────────────────────────────────────────────┐
│                 日常财务管理系统                        │
│                                                       │
│  ┌──────────────┐   ┌──────────────┐   ┌───────────┐ │
│  │  用户端前端   │   │  后端 API    │   │  数据库    │ │
│  │  (frontend)  │──→│  (backend)   │──→│  (MySQL)  │ │
│  └──────────────┘   └──────┬───────┘   └───────────┘ │
│                             │                          │
│                      ┌──────┴───────┐                  │
│                      │  后台管理系统  │                  │
│                      │   (admin)    │                  │
│                      └──────────────┘                  │
└─────────────────────────────────────────────────────┘
```

### 2.2 技术约束

- **不修改现有代码**：后台管理系统为独立项目，不改动用户端前端和现有后端代码
- **不修改现有数据库表**：不改动已有表（users、transactions、categories、reserve_funds）的结构和字段
- **允许新增一张表**：在数据库中新增 `super_admins` 表，仅用于后台管理系统登录，与用户端完全隔离
- **复用现有后端 API**：尽可能复用已有接口，不足部分由后台管理系统独立实现（独立端口或独立路由）

### 2.3 依赖的数据库表

#### 现有表（只读）

| 表名 | 说明 | 主要字段 |
|------|------|----------|
| `users` | 用户表 | id, username, nickname, avatar, status, last_login_at, created_at |
| `transactions` | 账单表 | id, user_id, category_id, category_name, type(expense/reserve), amount, transaction_date, note, created_at |
| `categories` | 分类表 | id, user_id(NULL=系统预设), type(expense/reserve), name, icon, color, bg_color, sort_order, is_default |
| `reserve_funds` | 储备金表 | id, user_id, month(YYYY-MM), amount, created_at, updated_at |

#### 新增表（后台专用）

| 表名 | 说明 | 主要字段 |
|------|------|----------|
| `super_admins` | 超级管理员表 | id, username, password_hash, nickname, last_login_at, created_at |

> `super_admins` 表仅服务于后台管理系统登录，与用户端 `users` 表完全独立，互不干扰。

## 三、功能模块详细设计

### 3.1 管理后台登录

> 后台管理系统使用独立的 `super_admins` 表进行管理员登录，与用户端登录完全隔离。

#### 功能点

| 编号 | 功能 | 说明 |
|------|------|------|
| F-1.1 | 超级管理员登录 | 使用 super_admins 表中的账号密码登录（用户名 + 密码） |
| F-1.2 | 登录态管理 | Token 鉴权，超时自动跳转登录页 |
| F-1.3 | 退出登录 | 清除登录态，跳转回登录页 |

#### super_admins 表结构

| 字段 | 类型 | 说明 |
|------|------|------|
| id | bigint, 主键, 自增 | 管理员ID |
| username | varchar(20), 唯一 | 管理员用户名 |
| password_hash | varchar(255) | 密码哈希（bcrypt） |
| nickname | varchar(15), 默认'超级管理员' | 显示名称 |
| last_login_at | datetime, 可空 | 最近登录时间 |
| created_at | datetime | 创建时间 |

#### 初始数据

- 系统部署时预置一条超级管理员记录（如用户名 `admin`，密码通过脚本生成哈希后插入）
- 密码通过 bcrypt 加密存储，与用户端密码方案一致

### 3.6 分类管理

> 管理系统预设的支出/储备金分类（user_id IS NULL 的系统级分类）。

#### 功能点

| 编号 | 功能 | 说明 |
|------|------|------|
| F-6.1 | 分类列表 | 展示所有系统预设分类，字段：ID、图标、名称、类型、主题色、底色、排序、创建时间 |
| F-6.2 | 新增支出分类 | 添加新的系统预设支出分类（type=expense），需填写：名称、图标(emoji)、主题色、底色、排序 |
| F-6.3 | 新增储备金分类 | 添加新的系统预设储备金分类（type=reserve），字段同上 |
| F-6.4 | 删除分类 | 删除系统预设分类（需二次确认），若该分类下存在账单记录则提示不可删除或需先处理关联数据 |
| F-6.5 | 分类校验 | 新增时校验：名称不能重复、不能为空；图标和颜色有默认值 |

#### 分类列表展示字段

| 字段 | 来源 | 说明 |
|------|------|------|
| 分类ID | categories.id | 自增主键 |
| 图标 | categories.icon | emoji 展示 |
| 名称 | categories.name | 分类名称 |
| 类型 | categories.type | expense=支出, reserve=储备金 |
| 主题色 | categories.color | 色值 |
| 底色 | categories.bg_color | 图标底色 |
| 排序 | categories.sort_order | 排序序号 |
| 关联账单数 | COUNT(transactions) | 使用该分类的账单数（关联查询） |
| 创建时间 | categories.created_at | 创建时间 |

#### 新增分类字段

| 字段 | 必填 | 默认值 | 校验规则 |
|------|------|--------|----------|
| 类型 | 是 | — | 选择：支出 / 储备金 |
| 名称 | 是 | — | 1-10 字，系统预设分类中不可重复 |
| 图标 | 否 | 📌 | emoji，最多 2 个字符 |
| 主题色 | 否 | #F2A6C0 | 7 位十六进制色值 |
| 底色 | 否 | #FDDDE6 | 7 位十六进制色值 |
| 排序 | 否 | 0 | 整数，越大越靠后 |

#### 删除分类规则

| 场景 | 处理方式 |
|------|----------|
| 该分类无关联账单 | 直接删除 |
| 该分类有关联账单 | 提示「该分类下有 N 条账单记录，无法删除」，阻止删除 |
| 系统预设分类（is_default=1） | 允许删除，但需二次确认提示「这是系统预设分类，删除后所有用户将看不到此分类」 |

## 六、全局交互规范

### 6.1 列表通用规范

| 规范 | 说明 |
|------|------|
| 分页 | 默认每页 20 条，支持切换 10/20/50 条 |
| 排序 | 默认按创建时间倒序（最新在前） |
| 空状态 | 无数据时展示空状态图标 + 提示文案 |
| 加载状态 | 请求数据时展示 loading 动画 |
| 操作反馈 | 成功/失败使用 Toast 提示 |

### 6.2 删除确认

- 所有删除操作需弹出二次确认框
- 确认框显示：操作后果说明 + 取消按钮 + 确认删除按钮（红色）

### 6.3 筛选与搜索

- 筛选条件变化后自动刷新列表，回到第 1 页
- 搜索支持防抖（300ms），避免频繁请求

### 6.4 视觉风格

- 后台管理系统采用简洁、专业的管理后台风格
- 与用户端的粉嫩风格区分，使用中性色系（白底 + 灰蓝主色调）
- 表格为主，卡片为辅，信息密度适中
